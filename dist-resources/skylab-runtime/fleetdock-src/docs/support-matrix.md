# 支持矩阵

| 产品/能力              | 成熟度      | 当前实现                                       | 适用范围                               |
| ---------------------- | ----------- | ---------------------------------------------- | -------------------------------------- |
| Mock Drone / Robot Dog | `simulated` | 内置 Mock 适配器                               | 零厂商依赖入门、业务流程和持续集成测试 |
| PX4 Generic            | `beta`      | MAVSDK/MAVLink 控制、事件及标准传感器流        | PX4 SITL 和受控真机验证                |
| Unitree Go2/G1         | `simulated` | Mock 适配器；`unitree-sdk2` 仅保留显式可选依赖 | SDK 学习和业务流程测试，不代表真机接入 |
| DJI 产品               | `planned`   | 仅 ProductProfile                              | 不能创建真实控制设备                   |
| 自定义产品             | `planned`   | 需自行注册适配器                               | 第三方扩展                             |

基础运行环境为 Python 3.11、3.12。PX4 可选依赖当前声明为 `mavsdk>=3.15.3`；正式部署应使用项目验证并锁定的 MAVSDK/PX4 组合。

PX4 当前覆盖连接、标准遥测、自动适配并确认物理完成的 Plan 起飞、即时原生 Takeoff、Land/RTL、
Mission、Offboard 速度/位置目标及路线执行。自动起飞已具备注入测试，并复用了指定真机 Demo 验证过的
控制时序；起飞完成会按全球位置与 Home 健康状态选择飞控 Hold 或保留本地 Offboard，支持只有光流
本地定位的室内控制链。本地位置起飞已有用户受控真机反馈，新的自适应交接分支目前只有注入测试，
整体不等于所有机型、固件和链路达到 D5/D6。正式真机验收必须记录机型、PX4 固件、MAVSDK
版本、链路/波特率、估计器与 Home 状态，并覆盖断链、遥测过期、模式拒绝、低电量、漂移、超时和取消。
标准传感器后端复用同一 MAVSDK/MAVLink 连接，覆盖 IMU、磁力计、GNSS、气压、测距和空速流。具体飞控
未持续输出某类消息时，应以 `device.sensors.status(...).is_stale(...)` 判断运行期可用性。相机像素不通过
MAVLink 遥测传输；PX4 后端可以从 MAVLink `VIDEO_STREAM_INFORMATION` 自动取得 RTSP 等视频 URI，
再通过可选 OpenCV 后端解码，也可以显式接入 RTSP、视频文件或本机摄像头。多机跟随、共享避障和 SDK
平滑航线属于高级能力，应在目标机型和现场安全边界内单独验收。

## PX4 环境与任务能力边界

| 公共 SDK 能力                     | 仿真         | 真机室内（本地定位） | 真机室外（全球定位） | 必要条件                                            |
| --------------------------------- | ------------ | -------------------- | -------------------- | --------------------------------------------------- |
| `Plan.takeoff()` / `hover()`      | 支持         | 代码支持             | 代码支持             | 健康本地定位，或健康全球定位与 Home                 |
| 本地 `move` / `route`             | 支持         | 代码支持             | 代码支持             | 新鲜的本地位置、速度和姿态遥测                      |
| `land()` / `ensure_land()`        | 支持         | 代码支持             | 代码支持             | 有效飞行链路；不要求 GPS/Home                       |
| GPS 航点 / PX4 Mission            | 支持         | 不适用               | 代码支持             | 新鲜全球位置与 Home；室内只有外部全球定位时才可用   |
| RTL / `ensure_return_to_launch()` | 支持         | 通常不适用           | 代码支持             | 新鲜全球位置与有效 Home                             |
| Fleet 批量 Plan                   | 注入测试支持 | 代码支持             | 代码支持             | 每台设备分别满足目标动作的就绪条件                  |
| Fleet 动态跟随                    | 注入测试支持 | 条件支持             | 条件支持             | 全部设备有全球位置，或显式声明同一 `local_frame_id` |

“代码支持”表示公共调用链、故障分支和注入测试已经覆盖，不表示所有机型与现场已完成实飞认证。
尤其是多机任务：两台 PX4 即使都报告 `LOCAL_NED`，其 EKF 原点也可能不同。FleetDock 只会在全球坐标
可换算到同一平面，或所有成员通过 `DeviceMetadata(local_frame_id="...")` 明确声明共享 VIO/动捕/地图
原点时启动跟随；无法证明共享坐标时会在预检阶段拒绝执行。普通批量起飞、航线和降落仍按每台设备
独立坐标与就绪状态执行，不要求共享原点。

`StandardCommand.timeout_s` 现在会限制 PX4/MAVSDK 同步命令等待；超时返回
`ErrorCode.COMMAND_TIMEOUT`。Plan 的步骤确认超时仍由 `run(step_timeout_s=...)` 或计划的
`timeout(...)` 控制，两者分别约束“底层命令等待”和“物理状态确认”。

本地可视化调试通过 `device.debug.camera()`、`device.debug.dashboard()` 或回调代理消费标准样本，支持
RGB/深度/双目画面以及无人机、足式设备和自定义传感器 HUD。该能力依赖 `vision` 可选依赖和图形桌面，
不会提高某个厂商真机后端的成熟度；某类数据能否显示仍以对应 `SensorBackend` 是否实际提供标准样本为准。

Unitree Go2/G1 与 DJI 当前没有真机传感器后端；公共 `SensorBackend`、标准足式设备模型和厂商/自定义命名空间已经预留扩展契约，但不能据此宣称完成真机接入。当前源码也没有导入 `unitree-sdk2`，因此该依赖不随 `integrations`、`full-prod` 或 `full-dev` 安装；待真实适配器和协议测试落地后再启用。
